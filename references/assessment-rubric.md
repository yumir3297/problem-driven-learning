# Assessment and Feedback

## Purpose

Assessment is part of teaching, not a final exam bolted onto the end. Use it to find the next best teaching move.

## Question ladder

Normally prepare 3–5 questions, ordered by cognitive demand:

| Level | What it tests | Typical form |
|---|---|---|
| 1. Recognition | Vocabulary, symbols, conditions, simple formula | Identify, define, substitute |
| 2. Basic operation | Correct use of one rule | Calculate, classify, trace code |
| 3. Reasoning | Why the method works | Explain, compare, justify |
| 4. Transfer | Use under changed conditions | Counterexample, variation, new context |
| 5. Synthesis | Integrate ideas into a full problem | Design, diagnose, prove, propose |

Use fewer questions for a small concept. A “complete problem” should be realistic for the learner's level and should require combining the target knowledge with its prerequisites—not merely be long.

## Adaptive delivery

- Present one question at a time.
- If the learner succeeds and explains the reasoning, move forward or increase difficulty.
- If the answer is correct but unsupported, ask for the decisive reason.
- If the answer is partially correct, identify the correct part and isolate the missing step.
- If the answer is wrong, diagnose the misconception before giving the solution.
- If the learner is stuck, provide a hint; then a worked example; then a nearby independent problem.
- If the learner has already demonstrated a skill, do not make them repeat several trivial questions.

## Feedback sequence

Use this order when a response reveals a gap:

1. **Locate:** identify the exact step or concept that failed.
2. **Explain:** state why the current reasoning does not work.
3. **Hint:** offer the smallest useful correction.
4. **Retry:** let the learner repair the reasoning.
5. **Model:** if needed, show a complete solution and explain the decisive step.
6. **Transfer:** ask one nearby variation to check whether the gap is closed.

Do not reveal the complete answer immediately if a small hint is likely to help. Do not withhold the answer indefinitely when the learner asks for a direct explanation.

## Mastery evidence

Judge mastery from observable evidence:

| Dimension | Evidence |
|---|---|
| Concept | Defines or recognizes the idea accurately. |
| Mechanism | Explains why it works, including key assumptions. |
| Application | Uses it correctly on a standard case. |
| Transfer | Adapts it to a changed or unfamiliar case. |

Report one of three statuses:

- **已掌握:** evidence supports accurate explanation and independent application; transfer is demonstrated when relevant.
- **基本掌握:** core idea is understood, but one dimension remains uncertain or needs support.
- **待巩固:** a prerequisite, core definition, or reasoning step is still unreliable.

Do not claim “已掌握” based only on “懂了”, repeated exposure, or a correct multiple-choice guess.

## Review and retention

- Offer a brief retrieval prompt at a natural later point in a multi-session topic.
- Suggest spaced review when the learner is building durable knowledge, but do not impose a universal schedule.
- Use interleaving only when comparing related problem types is instructionally useful.
- Feedback timing and practice format should match the learning goal.
- Do not turn every lesson into a flashcard deck unless requested.

## Compact lesson close

At the end of a meaningful segment, summarize:

1. Status: 已掌握 / 基本掌握 / 待巩固.
2. The central mechanism or rule.
3. The specific gap, if any.
4. The next best exercise or topic.

Keep the close short and evidence-based.
